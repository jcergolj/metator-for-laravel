# Derive resource names from immutable site directory identity

The basename of a site's directory under `/var/www` is its immutable site ID, and Metator derives application-specific resource names consistently from that identity rather than maintaining a comprehensive server-side resource mapping file. Minimal ownership metadata remains necessary to distinguish safe reruns from collisions, and numeric Redis database allocations require persisted allocation state. Renaming a site directory is therefore an explicit migration rather than an ordinary configuration update; this trades arbitrary resource naming for predictable conventions and less duplicated configuration.

Site IDs must start with a lowercase letter, contain only lowercase letters and digits with single hyphens between nonempty segments, and have at most 32 characters. Underscores, dots, spaces, uppercase letters, and silent normalization are rejected, allowing collision-free resource-name derivation within service naming limits. This constraint applies to site identity, not repository names or local checkout names. Installer suggestions use the environment-first form `<environment>-<repository-name>` and are left blank when the generated value exceeds the limit.
